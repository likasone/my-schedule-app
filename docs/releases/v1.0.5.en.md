# Release v1.0.5

English | [简体中文](./v1.0.5.md)

## Highlights
- **Save failures now print their own diagnosis**: no more guessing between permissions, file locks, or disk issues.
- This build focuses on observability. Data formats are unchanged, so upgrades leave existing diaries and settings untouched.

## New & Improved
### 1. In-process write diagnostics
- When saving a diary fails, the error message now includes:
  - the executable path;
  - the data directory the app actually uses;
  - the result of a write probe performed **inside the app process** on that directory;
  - the database file size and the time of its last successful write.
- The diagnosis does not depend on a log file, so it still shows up on machines where nothing can be written — exactly the case where it matters most.

### 2. Distinguishable build number
- The version is bumped to `1.0.5+105` so it is obvious which build is running.

## Fixes
- A summary of what was fixed since v1.0.0:
  - Release gate: test failures are no longer swallowed by `|| true`, and the generated-code check no longer commits and pushes on its own;
  - Tag colours written as fully transparent (value 0) made the `#` sign, the selected outline, and some labels invisible;
  - Unlocking a locked notebook bypassed the shared verification entry point; it now goes through `IdentityVerifier`;
  - After the very first sync the `lastSyncAt` checkpoint never advanced, which permanently blocked automatic sync;
  - Restored the Drift generated file `app_database.g.dart` that an automatic commit had deleted.
